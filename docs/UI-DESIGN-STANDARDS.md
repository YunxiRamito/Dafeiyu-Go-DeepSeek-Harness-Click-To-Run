# Windows 外观与导航图标规范

本规范适用于 Dafeiyu-Go 启动器、设置窗口及其预览/辅助窗口。涉及窗口风格、导航图标或圆角控件的改动必须遵循本文件。

## 导航图标：只用官方 Fluent UI System Icons

- **禁止手绘、自绘、AI 生成、拼接、描摹或自行改色/改路径的导航图标。** 不允许用临时 XAML `Path`、Emoji、单色 Segoe glyph、截图、从 Windows 设置中提取的私有资源来冒充多彩图标。
- 应从 Microsoft `fluentui-system-icons` 官方仓库选择语义合适的图标；优先用项目中 `SettingsNavIconsWin11` 约定的、未经修改的 `_24_color.svg` 多彩原始资源。
- Win11 多彩资源必须保留原始 SVG 内容。新增资源需固定上游 Git commit，在对应 `ATTRIBUTION.md` 登记官方图标名、源文件、许可证和 SHA-256；许可证保存在资源目录内，并确保进入构建产物。
- Windows 10 外观使用 Microsoft Fluent UI System Icons 的常规描边/线性图标资源，按浅色/深色主题选用项目对应资源。不得用 Win11 多彩图标替代 Win10 风格。
- 图标风格要根据**用户当前选择的 WindowStyle** 切换，而不是只检测操作系统版本。Win10 系统用户选 Win11 外观时用 Win11 图标；Win11 用户选 Win10 外观时用 Win10 图标。
- 新增一级导航项时，三种资源（Win11 彩色、Win10 浅色、Win10 深色）都必须有对应图标并验证实际显示；不完整时不要退化到自绘或普通字形。

## 首次默认与用户选择

- 首次启动尚无有效用户外观选择时，按 Windows build 自动默认：build `< 22000` 选择 `Windows10`，build `>= 22000` 选择 `Windows11`。
- 保存归一化后的具体风格，之后每次启动保留用户显式选择；不得每次启动都依据系统版本覆盖已有选择。
- 用户切换 Windows 10/11 外观后，窗口圆角、控件圆角和导航图标应在本次运行立即同步，无需重启。DWM 窗框圆角只在宿主系统支持时调用对应 API，资源/控件风格仍按所选外观一致应用。
- 兼容 `System` 或缺失值等旧设置：仅将其迁移/归一化为系统默认；迁移完成后持久化实际选定风格。

## 圆角和形状

- Windows 11 风格可以使用项目统一设计令牌规定的轻度圆角。
- Windows 10 风格中，**所有圆角矩形表面和控件必须为直角（CornerRadius = 0）**，包括卡片、按钮、输入框、信息条容器、Flyout/ContentDialog 内的矩形表面以及临时构造的 XAML Border。
- 控件样式优先使用 `CornerRadiusHelper` 的动态资源令牌（如 `ControlCornerRadius`、`OverlayCornerRadius`）；不得散落硬编码的非零圆角，避免切换风格后部分页面残留圆角。
- 真正圆形的元素（头像、圆形状态点、圆形进度指示器、圆形浮动按钮）仍保持圆形；不要把圆形对象机械地改成矩形。
- 进度条、图表等有独立几何形状的可视化按组件设计处理；若它是矩形容器，不得为了装饰而在 Windows 10 下新增圆角。

## 设置搜索框

- Windows10 风格使用直角搜索框；Windows11 风格使用胶囊形搜索框（当前高度 34、外壳圆角 17）。
- 占位提示和输入文字左对齐、垂直居中；内层 TextBox 背景、边框透明，边框宽度为零，不能出现第二层矩形或底部下划线。
- 普通、悬停、键盘聚焦和已输入文字状态均遵循上述外形；切换主题或风格后立即生效，不能仅修改首次创建的模板实例。

## 连接页信息边界

- 设备配对卡右侧按钮在已配对时显示“取消配对”，点击先确认；未配对时显示“配对”。presence 未知或离线不得让已确认的配对变回未配对。
- 配对弹窗每次打开读取当前状态；尚未配对时生成邀请，二维码图片和刷新按钮均可触发刷新。生成中禁用重复请求，过期后禁用复制并允许重试，关闭弹窗或切页后不得应用迟到结果。
- 已配对时隐藏生成二维码、邀请刷新及手动输入区域，避免出现“点击刷新”但禁用的误导提示。服务器缺少安全解除接口时明确提示并保留关系，不能仅删除本机记录冒充取消成功。
- 配对弹窗内错误在弹窗中展示；弹窗关闭后的操作失败必须在当前可视区域展示，必要时自动滚入提示，不能让提示落在屏幕之外。
- 文件缓存功能是可选能力。缓存接口缺失或服务器明确禁用时不阻断成员、申请与连接状态刷新；认证和成员权限错误仍须真实处理。清理请求成功后刷新服务器统计，不把逻辑删除等同磁盘清空。
- Aries 服务器描述固定为“连接互联服务器”，不显示 node_id/服务器标识；内部身份固定和安全校验保留。
- 设备配对、待审批请求、密钥确认和连接状态使用对端提供的 device_name（例如 OPPO Find X8）；不以 dev_xxx 填充名称。名称缺失时显示“对方尚未共享设备名称”，不得推测为本机或某款手机。
- “连接状态”只展示**被连接设备/对端**的信息，不展示本机 CPU、内存、GPU、网络、磁盘等信息，也不以本机数据填充远端空值。
- 远端信息没有经连接协议真实提供时，明确显示“对方暂未共享此信息”或“在线状态未知”；不得伪造或将服务器连通误报为对端在线。
- 本机 ID 必须从远端候选中排除，即使服务返回的 IsLocal 标记错误；没有唯一且已确认配对的远端时显示未连接/未知。
- 设备配对的服务器地址直接输入完整 URL（例如 `https://host:10240`），不提供独立端口控件；原有独立端口只作旧配置迁移，URL 中显式端口优先。本机 DSH 服务端口设置不受此规则影响。

## 完成前的界面验收

任何相关改动至少检查：

1. Windows 10 OS + Windows10 风格、Windows 10 OS + Windows11 风格、Windows11 OS + Windows10 风格、Windows11 OS + Windows11 风格的资源选择逻辑。
2. 首次设置默认值与已有显式用户设置重启后的保持行为。
3. 运行中切换风格后的设置页、导航图标、卡片、按钮、输入框和对话框外观。
4. Windows 10 风格下所有矩形零圆角；真正圆形元素仍为圆形。
5. 新增官方 SVG 的 Git 固定来源与 SHA-256；Win10 light/dark 资产均为官方来源。
6. Release 构建和产物检查。UIA/截图能力可用时，在浅色/深色、窗口风格切换前后做目视及自动化检查。

## 服务边界：DeveloperCenter 与 Aries

- **DeveloperCenter 开发者服务端**负责公告、通知、安装实例心跳和 PC/Android 平台在线统计。PC 心跳是 `/api/installations/heartbeat`，Android 是 `/api/android/heartbeat`；合并计数是 `/api/presence/platforms`。
- **Aries 服务端**负责设备签名、设备配对、小组消息/文件中继及配对成员 presence。它的设备心跳是 `/api/v1/public/devices/heartbeat`，组内状态是 `/api/v1/public/groups/{group}/presence`。不得将两套服务的地址、认证、DTO、统计或错误状态混用。
- 设置左下角在线提示只显示同一次服务器快照的合计人数，格式为“数字 在线”，不在此处分 PC 和移动端。
- DeveloperCenter 的“在线版本分布”使用同一张圆环图：PC 按启动器版本分别成块（例如 1.7.4、1.7.5、1.8.0），Android 全部 appVersion/versionCode 及未列出版本合并为一个“移动端”块。原始 DTO 的 Android 版本数据保持完整；展示聚合不改变心跳或统计协议。
- 图表中移动端无数据时显示“未知”，真实零人数显示 0；PC 多版本完整保留，图例可滚动，不截断成固定四个版本。圆环和图例支持悬停人数、占比及清晰的空状态。
- 新 PC 启动器的 DeveloperCenter 心跳携带 `platform: "windows"`。旧版本没有此标记时沿用 PC 端点口径；目前本地服务端 HeartbeatInput 不持久化该附加标记，不能宣称已据此存储系统版本。
- DeveloperCenter 新分平台接口未上线时，仅 404 回退旧 `/api/presence`。旧数值归 PC，移动端显示“未知”，不得伪造为零。旧历史 `/api/presence/history` 仅代表 PC 历史，必须明确标注 PC。
